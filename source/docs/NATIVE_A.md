# N-A: 세션 파일 접근의 네이티브 설계 (2026-10-13)

이 문서는 코드 변경 전에 작성한다. 범위는 §14.10 N-A의 L2/L3다.
L1, lib7의 조립/셈/시냅스/정체 씨앗, P-2의 유효성 판정은 그대로다.

## 1. 정의와 보존할 관측

- 파일 세션의 원본은 같은 파일 객체에 완전한 줄이 덧붙는 롤아웃이다.
  읽기 결과 R(f,o,n)는 그 객체의 [o,o+n) 바이트다. 미확인 줄은 기존
  `uw_get`이 먼저 제공한다. 메모리 세션은 파일을 열지 않는다.
- 세션 정체는 기존 P-12의 실제 경로와 D12의 파일 이름 id/상대 경로다.
  이미 Store에 등록된 정확한 경로는 그 Sess의 경로다. 별칭/링크/아직
  없는 경로에는 기존 실제 경로 해석을 적용한다.
- 조각의 버전은 첫 4바이트, 내용은 기존 parse_shard, 확인은 기존
  validate_shard/line_ok다. 확인 위치(처음/끝/중간 항목)는 데이터 위치다.
- 캐시 조각은 원본이 아니다. 읽기 매핑은 파싱 안에서만 살아 있고,
  재작성은 해당 매핑과 읽기 핸들이 모두 닫힌 뒤에 한다.
- 원본 파일 교체/삭제 후 같은 이름에 다른 이력을 붙이는 것은 기존
  lib7의 단조 front/pub 및 메타 상태가 지원하지 않는 입력이다. 새 구현은
  열린 파일 객체를 Sess 종료까지 유지한다. 원본 재바인딩을 정의하지 않는다.

## 2. 비용식

F=세션 수, V_f=조각 바이트, T_f=새 꼬리 바이트, Q=선택 출력 바이트,
K=호출 경로 길이, B=고정 검증 읽기 상한(4096바이트)로 둔다.

- 재시작: 원본 open ≤ F(동일 세션의 최초 동시 접근 경쟁은 참여자 수만큼
  후보가 생길 수 있고 CAS로 남은 1개 외에는 즉시 닫는다), 조각 open ≤ F,
  map ≤ F. 일 = O(F + ΣV_f + ΣT_f + 기존 복원 셈).
- 라이브 읽기/조립: 이미 열린 핸들 조회 O(1), 위치 읽기 O(Q), 꼬리 읽기
  O(T_f), 정체 조회 O(K) 기대값. 저장소 크기 N을 훑지 않는다.
- 원본 검증: 기존 3개 표본만 검사한다. 길이 < B이면 접두부와 개행을 한
  번 읽는다. 더 긴 줄은 기존처럼 64바이트 접두부와 개행 1바이트만 읽는다.
  읽기량 ≤ 3B이며 이력 길이와 무관하다.
- 조각 쓰기: 기존 Sess의 append 핸들과 레코드당 한 번 쓰기 의미를 유지한다.
  Windows 완료 사건은 스레드마다 하나로 재사용한다. 비용 O(레코드 바이트).

## 3. 보존 증명

1. `Sess.read_fd`는 -1에서 유효한 핸들로 한 번만 CAS 공개된다. 후보끼리
   같은 원본 객체를 연다. CAS 실패자는 자기 후보만 닫고 공개된 핸들을 쓴다.
   공개 핸들은 Store 종료로 모든 사용자가 끝난 뒤 Sess 소멸자에서 닫힌다.
   따라서 사용 중 닫힘, 공유 파일 커서, 새 대기/주인 선정이 없다.
2. Windows 원본은 FILE_FLAG_OVERLAPPED로 연다. 호출마다 별도 OVERLAPPED와
   위치를 사용하며 호출한 스레드 자신의 완료 사건만 기다린다. 함수가 끝날 때
   해당 I/O는 완료되어 버퍼/OVERLAPPED를 재사용해도 된다. 다른 스레드의
   위치·완료 상태는 읽지 않는다. Linux는 pread로 같은 바이트를 읽는다.
3. 4096보다 짧은 줄의 결합 읽기에서 검사하는 바이트는 기존의 접두부
   min(len,64)와 off+len의 개행 그대로다. 중간 바이트는 판정에 쓰지 않는다.
   긴 줄의 읽기/판정은 기존과 같다. 표본 집합과 조건식은 그대로다.
4. 조각의 동일한 매핑에서 매직과 레코드를 읽는다. 해제된 조각 매핑/읽기
   핸들은 삭제를 붙잡지 않는다. 복원 중에는 기존 restored/early 규칙에 의해
   이 Sess의 append 핸들이 아직 공개되지 않는다. 삭제 뒤 append 열기는
   삭제 보류된 자기 핸들을 가리키지 않는다. 외부 프로세스가 조각을 붙잡아
   삭제에 실패하면 기존 shard_err/다음 복원 경로로 드러나며 성공을 꾸미지 않는다.
5. `canon_path`의 정확한 등록 경로 조회는 이미 P-12로 등록된 경로만 반환한다.
   해시 결과의 Sess.path 바이트도 비교한다. 불일치/미등록은 기존 경로 해석이다.
   따라서 별칭의 합침과 D12 씨앗은 바뀌지 않는다.
6. 프레임 형식, R_WM, 기여·턴·조립 알고리즘에는 변화가 없다. 검증 실패,
   쓰다 만 줄/조각, 강제 종료는 기존 원본 재파싱 절차로 돌아간다.

## 4. 알고리즘 (코드에 앞선 결정)

1. Sess에 원본 read_fd와 이를 반환하는 source_fd를 둔다. 실패는 저장하지
   않아 파일을 다시 읽을 기회가 오면 재시도한다. 검증/꼬리/fetch가 사용한다.
2. load_shard에서 한 번 열기 → 크기 → 매핑 → 매직 → parse_shard → 해제한다.
   별도 shard_current의 열기는 없앤다. current 결과를 restore_file에 전달한다.
3. 원본 line_ok는 고정 B 이내에서 두 위치 읽기를 합친다. 그 외 판정은 보존한다.
4. Windows vp_open_ro는 OVERLAPPED, vp_pread는 명시 위치 + 호출자 자신의
   완료 결과를 쓴다. read/append는 FLS의 스레드별 완료 사건을 공유하되,
   각 함수는 완료 후 돌아오므로 중첩 진행 I/O가 없다. 사건 실패는 -1이다.
5. Windows canon_path는 등록 경로를 우선 확인한다. vp_realpath의 실제 경로
   해석은 보존한다. 원본 핸들은 삭제 공유를 허용하고, 자체 원본 삭제는 없다.

## 7. 꼬리 읽기 버퍼 결함과 L2 수정 (후속 코드 전에 기록)

KNA-tail (L2, 늦춤 — M8): 기존 꼬리 읽기는 남은 길이가 몇 바이트여도
16 MiB를 0으로 채운 뒤 읽고, EOF를 확인할 때도 다시 16 MiB를 채운다.
이것은 파싱이나 판정의 요구가 아닌 입력 버퍼 구현 비용이다.

정의는 R(f,o,n)과 완전한 줄 처리 그대로다. 관측한 크기를 E, 다음 읽을
위치를 p, 고정 최대 읽기 크기를 C=16 MiB라 하면 요청량을 min(C,E-p)로
한다. p>=E이면 크기를 새로 읽고, 여전히 p>=E일 때 종료한다. 큰 줄이나
NUL 범위가 읽기 경계를 넘으면 기존 buf/scan/start 상태로 이어 읽는다.

증명: 파일이 덧붙기만 하면 크기 재확인 전의 [p,E)는 원래 pread의 접두부다.
완전한 줄의 판정은 청크 경계와 무관하고 미완성 접미부는 buf에 남는다.
크기를 재확인하면 읽기 중 늘어난 부분도 같은 방식으로 읽는다. EOF 관측
이후 추가된 줄은 기존 두 번째 복원 읽기/감시 사건이 처리한다. 따라서 처리한
완전한 줄과 바이트 위치는 동일하다. 파일당 불필요한 16 MiB 초기화를 없애며
비용은 O(실제 읽은 꼬리 바이트), 크기 확인은 청크당 O(1)이다. 새 대기는 없다.

## 8. 매핑 실패 시 버전 확인 보존 (후속 코드 전에 기록)

KNA-map (L3, 늦춤): 하나로 합친 load_shard가 매핑 실패 시 바로 돌아가면,
기존 shard_current가 판별하던 옛 매직을 확인하지 못한다. 원본 재파싱 판단은
보존되지만 옛 조각을 지우지 않고 이어 쓸 수 있다. 매핑이 실패한 경우에만
이미 열린 핸들로 4바이트를 위치 읽기한다. 기존과 같이 읽은 양 <4 또는
매직 일치이면 current, 4바이트의 다른 매직이면 재작성이다. 정상 경로의
열기/읽기 수는 늘지 않으며, 실패 경로도 추가 열기 없이 O(1)이다.
