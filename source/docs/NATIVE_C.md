# N-C 데몬 네이티브 설계 (2026-10-13, 코드 전)

## 정의 경계

L1 C2′/C2″/C3′, KX2a/b, lib7 판단은 고정한다. 원본은 기존 정의대로
append-only transcript다. C(T), 순번, cc 위치/sha, 64×8 LE 덮개 형식은
바꾸지 않는다. 파이프와 다리 프로토콜도 유지한다.

## 수식

- 파일 f의 열거 크기 s_f, 덮개 v_f=max(slot[0..63]). v_f=s_f이면
  원본 끝까지 출력이 쓰였다는 T-cv1의 사실로 변환을 생략한다.
  v_f>s_f는 SOURCE_TRUNCATED이며 성공으로 간주하지 않는다.
- 통상 변경 사건 비용은 O(|path|+64+tail_bytes+lib insert)다.
  시작 열거는 O(F0+directory_entries), 덮개 읽기는 최대 512 bytes/file이다.
  덮개를 모으는 새 전역 로그/색인은 만들지 않는다.
- 넘침으로 파일 이름 정보가 사라진 경우 복구 열거는 O(directory_entries).
  **N5의 전체 재열거와 모든 사건에 N 항 금지는 동시에 충족할 수 없다.**
  잃은 이름을 별도 신뢰 가능한 변경 색인 없이 찾으려면 관측하지 않은 파일이
  변경됐을 가능성을 배제할 수 없기 때문이다. 정상 사건의 N 항은 없애고,
  넘침 복구의 N 항을 L2/늦춤으로 명시한다. N5 시험 기준은 바꾸지 않는다.

## 증명 의무

1. 열거 전에 감시를 등록한다. 열거 크기 이후의 추가분은 감시 사건으로
   다시 표시된다. 빠른 경로는 열거에서 본 끝의 F0 사실만 닫는다.
2. 넘침 후에도 같은 감시 핸들을 유지하며 재열거한다. 재열거 이전 변경은
   열거에 포함되고, 재열거와 겹친 변경은 계속 수집되는 감시 사건에 포함된다.
   다시 넘치면 다시 재열거한다. 넘침 그 자체를 영구 요청 오류로 만들지 않는다.
3. 핸들은 Entry 소유 CAS publication으로 공유한다. 경쟁한 후보는 즉시 닫고
   채택된 핸들은 요청/상주 작업 종료 뒤 Entry 파괴 때 닫는다. 위치 I/O만
   사용하므로 공유 파일 포인터가 없다. 소스/출력/덮개는 필요할 때만 연다.
   원본 재작성은 L1 범위 밖이며 크기 감소/정체 교체는 명시 오류로 취급한다.
4. prepare_tail의 덮개→C(T) 읽기 순서와 출력 완료→덮개 쓰기 순서는 유지한다.
   같은 핸들 재사용은 바이트, 위치, 순번, sha 또는 lib 입력을 바꾸지 않는다.
5. F0 닫힘→lib open의 자료 의존은 §14.9 그대로 필요하다. 완료 카운트는
   집합의 미완료 수이며 도착 순서를 판단에 사용하지 않는다. 기존 큰 꼬리의
   합산 완료 continuation 역시 데이터 의존이다. 이 의존까지 금지하면 lib7의
   기존 이력 공급 API(P-2/P-8)를 바꾸어야 하므로 C 범위 밖으로 보고한다.

## 알고리즘

- Windows 디렉터리는 FindFirstFileExW(FindExInfoBasic,
  FIND_FIRST_EX_LARGE_FETCH)/FindNextFileW로 열거하며 크기를 함께 전달한다.
  reparse point는 건너뛴다. 신뢰된 루트 아래 열거 경로는 파일별 realpath로
  다시 열지 않는다. 외부 요청은 기존 canonical/루트 검사를 유지한다.
- 열거 작업과 통상 알림은 각각 Entry의 크기 표본/dirty 비트로 전달한다.
  통상 알림은 현재 소스 끝을 핸들에서 확인한다. 초기 표본 때문에 뒤의 사건이
  지워지지 않도록 dirty 교환과 크기 표본 사용을 구분한다.
- Entry에 원본·출력·덮개 핸들을 지연 유지한다. 작은 꼬리는 prepare_tail의
  결과를 바로 변환하며 같은 꼬리를 두 번 준비하지 않는다. 읽기/쓰기는
  Windows OVERLAPPED 위치 I/O, Linux pread/pwrite다.
- Windows 감시는 src 안에서 직접 소유한다. 초기 등록→초기 열거→알림 처리,
  zero-byte/ERROR_NOTIFY_ENUM_DIR→재열거. Linux IN_Q_OVERFLOW도 재열거한다.
  삭제된 알림 이름은 정상적인 소멸로 처리하고 실제 감시 실패는 오류로 남긴다.
- VRS_CC_TEST_METRICS에 시작 경과, 열거, lib 열기 직전, open 호출, 복원,
  덮개 읽기 합계/횟수/빠른 경로 횟수/넘침·재열거를 기록한다.

## 대기 및 검증 (실행 전 고정)

새 직렬 작업 구조는 도입하지 않는다. Windows watcher의 OS 알림/종료 대기는
기존 vp_watch_tree의 대기를 src로 옮긴 것이다. OVERLAPPED 완료 대기는
기존 File의 동일 연산 완료 대기다. 정확한 파일:줄은 구현 뒤 추가한다.

tools/kwov_test.py는 Python 3.11 표준 라이브러리만 사용한다. 실제 OS 넘침을
유발하고 관측한 로그를 요구한다. Linux는 자기가 띄운 데몬만 SIGSTOP한 동안
inotify 용량 이상 사건을 생성하고 SIGCONT한다. Windows는 작은 감시 버퍼와
긴 이름/많은 실제 변경을 쓴다. restore 호출로 누락을 보정하지 않고 모든
덮개=원본 끝, C(T)의 cc 원본 위치/sha/본문을 확인한다. 복구 뒤 추가 사건도
검사한다. static/samples/kx4/kwov 중계, Linux 변환 동시성/바이트 회귀 및
M1·kx2 동결본 N1을 실행한다. 결과가 기준을 못 채우면 그대로 기록한다.

참고: Microsoft ReadDirectoryChangesW 문서의 핸들 생애 동안 유지되는 버퍼,
zero-byte/ERROR_NOTIFY_ENUM_DIR 재열거 규칙:
https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw

## 검증 중 발견한 기존 시험 결함 (코드 수정 전)

L3/검증 막음: src/tests/u_native.cpp core는 짝 없는 `\ud800`을 거부해야
한다고 검사한다. 이는 이미 고정된 §14.9 KX2b(U+FFFD로 읽기)와 모순된다.
JSON 구현은 바꾸지 않고 이 오래된 검사만 KX2b의 명시적인 양성 검사로
바꾼다. 잘못된 일반 JSON 거부 검사는 유지한다. 동시 변환 시험에는
EntryFiles를 실제 공유하여 핸들 재사용 경로도 같은 바이트인지 검사한다.

기존 run_u.py도 KX1 전의 '접속 가능=lib 열림'을 전제했다. 시험 서버의
기동 완료 관측만 VRS_TEST_OPEN으로 맞춘다(제품 대기 추가 아님).
외부 표본을 읽기 전용으로 지정하는 환경 변수를 더해 보호된 ref/나
다른 작업 트리를 복사/수정하지 않고 동일 U1–U6를 실행한다.

## N4 검토에 따른 L2 수정 (구현 전)

기존 '마지막 완료 스레드가 곧바로 후속 일을 수행' 규칙은 제거한다.
F0 fact 하나 또는 변환 조각 하나가 완료될 때마다 순서 없는 기존 Resident
작업 집합에 readiness 검사를 제출한다. 검사자는 모든 입력이 준비되지
않았으면 즉시 반환하고, 준비됐으면 1회 publication CAS로 후속 계산을
시작한다. 재시도 루프, 잠든 검사자, 전체 파일 순회는 없다.

증명: 각 완료는 release로 남은 수를 감소시킨 뒤 검사를 제출한다. 모든
완료가 일어난 뒤 적어도 하나의 검사가 실행 가능하다. 모든 완료를 본
검사자는 같은 불변 입력 집합을 읽는다. 어떤 완료자/검사자가 실행하든
같은 바이트와 같은 F0 집합이다. CAS는 lib 핸들 초기화와 callback의
정확히 한 번 알림만 보장한다. 기존 작업 집합의 임의 순서를 유지하고
완료 시각/스레드 정체를 선택 기준으로 사용하지 않는다.

비용은 완료당 O(1) 검사 제출/판정이다. 저장소 N을 순회하지 않는다.
동시 conv_tail/다른 그룹의 동일 파일 위치 쓰기는 계속 허용한다.
한 검사자가 다른 검사자를 기다리거나 소유권을 넘겨받지 않는다.

엄격히 남는 의존: F0의 모든 prefix가 닫혀야 lib7 P-2를 열 수 있고,
한 그룹의 바이트 합을 알아야 구멍 없는 C(T) 한 범위를 쓸 수 있다.
이는 readiness 조건으로 남는다. 이 **자료 의존 자체**를 '단계 대기'로
금지하는 해석까지 충족했다고 주장하지 않는다. 개별 청크가 임의 위치에
먼저 쓰면 C3′의 단일 연속 prefix/cover=max만으로는 완전함을 증명하지
못하므로 별도 완료 표현(L1 C3′ 변경)이나 기존 lib7 공급 정의 변경이 필요하다.

중계가 summary/build만 반송하므로 N2 단계 수치를 보존하기 위해 KW-ov
검사기의 출력에 같은 요청 디렉터리의 kx4 *.err 단계 로그가 있으면 함께
싣는다. N5 통과 조건은 동일하며, 최종 요청 순서는 kx4 뒤 kwov로 한다.

L3/막음(종료 안전성): native watcher의 비동기 버퍼는 취소 완료보다 먼저
파괴되면 안 된다. Watch 소유 객체 안에 버퍼를 두어 destructor 본문에서
CancelIoEx/GetOverlappedResult가 끝난 다음에만 메모리를 해제한다.

L3/막음(종료 수명): readiness callback이 Resident를 참조하므로 소유
unique_ptr를 비우기 전에 상주 작업의 기존 종료 join을 끝낸다. reset 도중
실행 중인 callback이 비워진 소유 포인터를 읽는 경쟁을 없앤다. 실행 중
대기는 추가하지 않으며 기존 종료 대기의 호출 위치만 명시한다.

Windows 위치 I/O의 완료 사건도 매번 만들고 닫지 않는다. FLS로 실행
스레드마다 사건 하나를 유지하고 각 동기적으로 완료되는 OVERLAPPED 연산
시작 전에 ResetEvent한다. 같은 스레드에는 앞 연산 완료 뒤에만 다음 연산이
시작되므로 재사용이 안전하다. 서로 다른 스레드는 다른 사건을 사용한다.
이는 스레드별 I/O 완료 자원이며 작업 소유권/잠금/새 대기가 아니다.
