# N-H: 2차 통합과 준비 조건 판정

2026-10-13. 출발 `67e4700`, RULES/ROUND2 및 §13, §14.0–14.10을 따른다.
L1/lib7 판단과 고정 시험 기준은 바꾸지 않는다.

## 정의

준비 조건은 읽을 데이터가 완성되었음을 뜻한다. 준비 전 검사는 반환하고,
자료를 완성한 실행은 조건 변경을 알린다. 후속 실행은 상주 실행기의 독립
작업 선택에서만 일어난다. 완료자 정체/도착 순서는 선택 규칙에 쓰지 않는다.

H-N4-INLINE (L2/L3, G 막음): 출발판 `Resident::submit`의 4096자리 포화
fallback은 함수를 즉시 실행한다. F0 finish_one과 변환 조각 완료가 제출한
검사도 이 길을 타므로, 마지막 완료자가 open/publish를 직접 실행할 수 있다.
restore_left는 작업을 미리 심고 완료마다 signal만 보내므로 이 결함이 없다.

## 수식

R=미복원 파일 수, P=미완성 F0 사실 수+스캔 사실, L=미완성 변환 조각 수.
R=0, P=0, L=0은 각각 필요한 입력 집합의 완성을 나타내며 도착자 id는 없다.
완료 시 release RMW 뒤 알림, 검사 시 acquire load로 입력 바이트를 관측한다.

검사 저장소는 고정 K=4096자리이며 예약 비트와 작업 포인터를 분리한다.
자리 예약 비용 ≤K, 알림 비용 O(1), 선택 비용은 고정 비트맵 크기 이하이다.
파일 수/이력 길이 N에 비례하는 탐색이나 누적 보존은 없다.

## 증명

1. 검사 자리는 생산자를 시작하기 전에 예약한다. 자료 완료자는 자리의
   비트를 켜고 일꾼을 깨우기만 한다. 알림에는 직접 실행 fallback이 없다.
2. 일꾼은 비트를 가져간 뒤 포인터를 exchange(nullptr)로 가져가 독립 검사를
   수행한다. 다른 일꾼은 빈 포인터면 즉시 반환한다. 잠금/소유자 대기가 아니다.
3. 준비되지 않았으면 포인터를 돌려놓는다. 이 사이 도착한 알림을 다른 일꾼이
   소비할 수 있으므로, 포인터 반환 뒤 준비 조건을 한 번 더 검사하여 참이면
   비트를 켠다. 조건이 단조로 거짓→참으로만 바뀌므로 최종 알림은 유실되지 않는다.
   두 번째 검사도 실행을 하지 않고 알림만 한다. 반복 대기 루프는 없다.
4. 예약 비트는 검사 작업이 끝날 때까지 유지하므로 실행 중 빈 포인터 자리를
   새 작업이 덮지 않는다. 종료 후 늦은 알림이 재사용 자리에 와도 새 작업의
   자체 준비 조건을 검사할 뿐이다. 완료 통지는 저장된 포인터를 읽지 않는다.
5. 검사 작업은 실행 완료 시 삭제되고 자리를 반환한다. 준비 조건/실행 함수의
   지역 사본은 재공개 직후 다른 일꾼이 작업을 삭제해도 검사 자료의 수명을 지킨다.
6. F0 검사는 데몬 시작 때 하나 예약한다. 그룹 검사 예약이 포화라면 조각을
   시작하기 전에 호출자의 기존 conv_prepared로 해당 독립 꼬리를 처리한다.
   이는 완료자에게 후속 단계를 맡기는 규칙이 아니며 다른 작업을 기다리지 않는다.
   정상 그룹은 조각들이 병렬로 build하고 별도 검사 작업이 기존 publish를 한다.
   변환/ordinal/cover/판단 함수와 바이트는 바꾸지 않는다.

## 알고리즘 (코드 전 고정)

- Resident에 prepare_ready(predicate, action)와 notify_ready(id)를 더한다.
  별도 고정 비트맵의 검사 작업을 기존 작업 선택에서 처리한다.
- finish_one은 P 감소와 notify_ready만 한다. F0 검사 action은 기존 open CAS다.
- conv_parallel은 그룹의 L/published와 검사 자리를 먼저 준비하고 조각을 제출한다.
  조각 완료는 L 감소와 notify_ready만 한다. 검사 action은 기존 publish/done이다.
- 기존 독립 조각 submit 포화 fallback은 유지한다. 후속 검사에는 사용하지 않는다.
- 포화/알림 유실 경계를 실행하는 국소 회귀 검사와 Linux 빌드를 한다.
- F/G의 정확한 통과 rev를 --no-ff merge하고 통합 static/N1 및 전체 지정 시험을
  수행한다. Linux 동결본 JSON은 끝의 ,"us":N만 빼고 바이트/rc/hash를 비교한다.
- N1–N5 및 사건 비용 규칙을 모두 충족할 때만 main 병합과 native-pass 태그를 한다.

## 대기 자리

새 대기를 넣지 않는다. 준비 전 반환하며 기존 Resident 일꾼의 signal 대기만
재사용한다. 시험 전용 drain/종료 join은 기존 그대로다. 최종 파일:줄과 전체
판정은 REPORT_H.md에 남긴다.
