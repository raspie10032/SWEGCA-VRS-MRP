# N-E 통합과 판정

2026-10-13. 기준: `docs/VRS_MCP_libvrs_v1.md` §13, §14.0–14.10 및
`relay/tasks/RULES.md`. L1/lib7 판단은 동결한다.

## 정의

통합 대상은 na/nb/nc/nd의 L2/L3 변경이다. 각 가지의 커밋과 중계 결과의
`rev`를 대응시키고 static 및 해당 N1 통과가 확인된 커밋만 merge한다.
기준 입력, 기준 출력, 시간 문턱을 변경하지 않는다. 합친 판에서는 전체
N1–N5와 리눅스 판단 같음을 다시 확인한다.

## 수식

입력 집합 S∈{m1(409),kx2(1206)}, 실행 모드 m∈{batch,reopen}에 대해
J(S,m,f)=JSON 끝의 `,"us":N`만 제거한 바이트다.
N1의 비교는 모든 f의 J=J_frozen, cells_hash=cells_hash_frozen,
입력 목록 순서의 assemble rc 목록=동결본 rc 목록이다.
N2는 kx4 재시작 측정 t₁,…,t₅ 각각 tᵢ≤5.0초다.
통합 허용은 N1∧N2∧N3∧N4∧N5∧Linux_build∧Linux_equivalence다.

## 증명 의무

각 변경의 자료구조/비용/대기 분석은 해당 NATIVE_A/B/C/D 문서와 실제
코드를 대조한다. 같은 함수에 변경이 겹치면 두 가지의 불변식을 유지하는
수동 병합 근거를 여기에 먼저 적는다. 시험 통과는 고정 말뭉치에서의
동등성 증거이며 모든 가능한 입력에 대한 수학적 증명으로 확대하지 않는다.
비교기는 시간 필드 외의 데이터를 정규화하지 않고, 프로세스 실패·누락·
추가 출력·rc 목록 차이를 실패로 보존한다.

## 알고리즘

## 코드 경계

이 문서만으로 런타임 알고리즘은 바뀌지 않는다. E의 빌드/비교 도구는
독립 시험 프로세스이며 라이브 런타임에 새 대기·큐·잠금을 넣지 않는다.
CPU 0–11만 사용한다. 공통 보고서는 요청된 저장소 루트 REPORT_E.md,
공유 연락은 relay/notes에 둔다. 기준 문서/ref/동결본은 읽기 전용이다.

## E-W6-BASE 진단 (2026-10-13, 코드 전)

출발점 Windows e-001의 v603 100회가 bad 5다. Linux 동결본과 출발판은
같은 100회에서 bad 0였다. 중계는 v603 출력 끝 400바이트만 보존해서 어느
호출/항목이 실패했는지 사라진다. L3 관측 결함을 먼저 고친다.

판정 함수 ok=(rc==0 ∧ 기대 발화가 같은 순서로 모두 있음)는 그대로 둔다.
첫 실패 뒤에만 기존 debug 상태(pend/lines_in/lines_applied)를 읽고, 기존
300ms 뒤 재조회가 같은 조건을 만족하는지도 기록한다. 최초 bad는 절대
취소하지 않는다. 최대 3개 실패의 위치/누락/pend/재조회 결과를 마지막
400바이트 안에 요약한다. 새 반복/대기는 없고 기존 재조회 300ms는 유지한다.
이 관측은 삽입 완료와 처리된 앞부분 공개의 차이인지, 안정 후에도 남는
판단 차이인지를 구별한다. L1 변경이 필요한 경우 그 근거를 보고한다.

## A+D 겹침 병합 설계 (2026-10-13, 병합 전)

A-1의 318fa02와 D-002의 b331a29는 각각 static/N1을 통과했다.
둘의 ingest_file_tail 변경이 겹친다. A는 보관한 원본 핸들과 관측 크기로
읽기 길이를 제한하고, D는 유효 바이트만 가진 스레드별 저장을 재사용한다.

불변식: buf[0,size)는 기존 입력 바이트, base_off+size는 다음 읽을 위치,
end는 현재 관측한 EOF다. want=min(CHUNK,end-(base_off+size))이고 want>0인
경우에만 reserve_more(want) 후 pread(...,want,...)를 한다. got>0일 때만
appended(got), 소비 후 remove_prefix(start)를 한다. 관측 EOF에 닿으면 A의
fsize 갱신/종료 판단을 보존한다. source_fd의 핸들은 이 함수에서 닫지 않는다.

증명: reserve는 입력 내용을 늘리지 않고 got만 유효 길이를 늘린다. 소비된
prefix를 떼는 것은 기존 erase와 같은 바이트/위치 변환이다. 따라서 A의 읽기
범위와 D의 초기화 없는 저장을 동시에 보존한다. 비용은 실제 꼬리와 기하급수
용량 증가의 복사이며 새 N 항/공유 저장/대기는 없다.

D의 부분 벡터 예약·fid_key view·빌드 스크립트는 그대로 합친다. 도구의
할당기 관측은 판단 상태에 들어가지 않는다. 이후 B의 reopen 계측과 겹치면
별도로 w1/w6 관측 경계 및 할당기 통계 보존 근거를 적는다.

## B+D 관측 도구 병합 (2026-10-13, 병합 전)

B-002의 2e24452는 static/N1/W3/W4를 통과했다. lib의 작업 집합 변경은
A/D의 I/O·저장 변경과 다른 함수에 있으며 각각의 불변식을 함께 유지한다.
reopen.cpp는 B의 w6→w1 실행과 기존 vrs_wait(NULL)의 ready 관측을 사용한다.
각 실행의 시간/CPU/폴트 측정은 open 시작→ready까지만이다. D의 메모리
절대값 관측은 해당 시간 구간 밖에서 before_open/ready/closed로 남기고,
mi_version 및 mi_stats_merge/print도 측정 뒤에 남긴다. 관측은 판단을 쓰지
않고 예전 busy poll은 제거한다. OS 대기 자체는 기존 vrs_wait이며 시험
도구 호출만 바뀐다. 같은 주 실행 인자 6의 첫 ready_ms가 중계 값이다.
