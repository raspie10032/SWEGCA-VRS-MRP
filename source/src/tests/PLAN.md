# 고정 시험 기준 (실행 전)

기준 문서: ref/VRS_MCP_libvrs_v1.md §14.3. 제공된 표본은 4개이며
S_cc 전체와 무작위 20개는 제공되지 않았다. 표본 4개를 모두 검사하고
전체 S_cc 검증으로 주장하지 않는다. 시드 20261013.

- U1: 각 표본에 대해 전체 변환, 원본 바이트를 임의 크기 50번으로
  덧붙이며 변환, 8개 스레드의 동시 conv_tail 결과가 바이트로 같아야 한다.
- U2: 크기 상위 3개에서 상주 풀의 덩어리 변환과 단일 호출 결과가 같다.
  8 MiB보다 작은 파일도 이 시험에서는 덩어리 경로를 직접 실행한다.
- U3: 모든 출력의 순번은 meta=0, 이후 1부터 연속이다. cc.h는 개행을
  제외한 원본 [o,o+n)의 SHA-256이다. 출력 바이트 위치는 앞 줄 끝이다.
- U4: 각 표본의 마지막 출력 발생 원본 줄을 중간에서 잘라 덧붙이고
  변환한다. 반쪽 줄에서 출력이 없어야 하고 나머지와 원본 뒤쪽을
  덧붙인 결과는 전체 변환과 같아야 한다.
- U5: 실제 데몬 restore. 압축 없는 표본은 정상 빈 결과,
  나머지는 모든 항목 o < 마지막 경계이고 user/assistant여야 한다.
  독립 Python 검사기로 sha와 본문까지 확인한다.
- U6: 95,000 단위 한 쪽에 끝나는 입력에서 4,000 단위 여러 쪽의
  항목 목록이 동일해야 한다. 개별 항목도 4,000 안에 드는 입력이
  필요하다. 원본 표본에 적합한 입력이 없으면 그대로 보고한다.
  별도로 고정 합성 입력(한글/비BMP 포함 24턴, 압축 1회)을 검사한다.

추가 검사: JSON 오류/이스케이프, C2 분기, 출력 중간 절단 복구,
잘못된 sha/경로/start/budget, 거대한 단일 항목 오류, read 바이트/쪽,
MCP tools/list와 정체 발견/불일치, 데몬 재기동, 실시간 삽입.
추가 검사 결과는 U1–U6의 정의나 기대값을 바꾸지 않는다.
